# Task 4: PWA identity and cache migration

Date: 2026-09-24

## Changes

- Updated the web manifest name and short name to `月影工房`, and its description to match the idle game. The launch URL, scope, and icon URLs remain relative to the GitHub Pages subpath.
- Moved the service worker to the distinct `moonlight-idle-v3` cache. Its install shell includes the app entry page, stylesheet, all six runtime JavaScript modules, manifest, and 180, 192, and 512 pixel icons.
- On activation, the worker removes obsolete caches with either the previous `moonlit-sorting-office-` prefix or the new `moonlight-idle-` prefix, while keeping `moonlight-idle-v3` and caches owned by other apps.
- Kept same-origin GET handling network-first: successful responses update the current cache, network failures use the cached request, and offline navigations fall back to `index.html` resolved from the registration scope. Cross-origin GETs and non-GET requests continue to pass through.
- The worker does not access browser storage. `src/storage.js` was not changed; the existing storage test confirms that loading the new game ignores and preserves `moonlit-sorting-office:v1`.

## Automated verification

- Red phase: `node --test tests/pwa.test.js` produced 8 passing and 3 failing tests. The failures identified the old manifest identity, old cache name, and missing cleanup for earlier `moonlight-idle-` caches.
- Green phase: `node --test tests/pwa.test.js` passed 11/11 after the changes. Coverage includes the complete relative app shell, URLs resolving under `/moonlit-sorting-office/`, cache ownership cleanup, network-first caching, cache-write failure, scoped offline navigation fallback, and request pass-through.
- Full suite: `npm test` passed 51/51. The balance simulation reported first prestige at 1,713 simulated seconds and second prestige at 1,085 seconds.

## Review correction: cache opening failure

The first cache-write failure test covered `cache.put()` rejection, but not `caches.open()` rejection. In the latter case, the rejection reached the outer network-failure handler even though `fetch()` had already returned a successful response. With no matching cached request, that handler discarded the online response and rejected.

- Added `network-first returns a valid response when opening the cache fails`. RED: `node --test tests/pwa.test.js` passed 11 tests and failed this test with `Network request failed and no cached response is available`.
- Updated the successful-response path to absorb failures across both opening and writing the cache, then return the original network response.
- Green: `node --test tests/pwa.test.js` passed 12/12; `npm test` passed 52/52.
