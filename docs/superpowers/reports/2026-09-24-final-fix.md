# Final whole-branch fix

Date: 2026-09-24

Base: `6a764db`

## Changes

- `buyGenerator` now checks that the next owned count remains a safe integer before charging currency or returning a new state. At `Number.MAX_SAFE_INTEGER`, the purchase is rejected unchanged, including when the overflow cost fallback equals `Number.MAX_VALUE`.
- `persist()` now maps `invalid-save` to `保存データに問題があり、保存できません`; only a successful save reports `端末内に自動保存`.
- Replaced the ambiguous upgrade description with copy explaining that each upgrade is bought once per run and remains active until prestige.
- Collection clicks no longer write a repetitive message to the `role="status"` activity region. Purchase and prestige feedback remain announced.
- Added UI integration coverage using the existing fake DOM and storage harness:
  - `collection clicks stay quiet in the live region while upgrade purchases are announced` clicks the click-power upgrade from a valid seeded game and checks its effect, purchase announcement, and persisted state.
  - `star condenser UI blocks an unaffordable purchase and persists a funded purchase` checks the disabled and no-op state at 9,999 moonlight, funds and clicks the condenser, then advances 20 seconds and checks the star and save.
  - `an invalid in-memory save never reports that it was saved` forces the persistence rejection path and verifies the status. This test-only invalid state is separate from the guarded purchase flow.

No game balance values changed.
