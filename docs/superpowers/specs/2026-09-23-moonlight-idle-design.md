# 月影工房 インクリメンタルゲーム設計

## 目的と成功条件

公開済みの「月影仕分け局」を、同じリポジトリ・URLで日本語のインクリメンタル／放置ゲームへ全面置換する。利用者が序盤は大きなボタンを押して月光を作り、設備購入による自動生産へ移り、星屑の解放と転生を経て再周回の加速を体感できることが成功条件。前作の仕分け判断・勤務終了ループは残さない。利用者は機能と制作方法の詳細判断を委任済み。

## プレイループと数値

- 通貨「月光」は最初のクリックで1獲得。保有数、毎秒生産、クリック生産、周回累計を常時表示。
- 月光設備は「ランタン」(初期価格15、0.2/秒)、「観測机」(180、2.5/秒)、「月輪塔」(2,400、30/秒)、「夜空庭園」(36,000、400/秒)。n台目の価格は `ceil(baseCost * 1.15 ** n)`。所持・購入可能数を表示し、予算不足は無効化。
- 月光強化はクリック2倍、設備生産2倍など、明示した費用と購入条件を持つ買い切り。成長段階でカードが解放され、初期画面はクリックと最初の設備を主役にする。
- 周回で獲得した月光が5,000に達すると第2通貨「星屑」と星屑設備「星屑凝縮器」を解放。凝縮器は月光10,000から購入し、0.05星屑/秒を生産する。星屑を支払い、月光生産を強める強化を少なくとも1個用意。
- 周回で獲得した月光が100,000以上かつ星屑が累計25以上になると転生可能。獲得する恒久記憶は `max(1, floor(sqrt(runMoonEarned / 100000)))`。転生で現在の月光・星屑・設備・周回強化・周回累計を初期化し、記憶累計、総転生数、恒久倍率は維持。恒久倍率は `1 + 0.25 * memories`、クリックと月光設備の双方に掛かる。転生前に失うものと得るものを画面で示し、確認操作を置く。
- 長時間放置後は経過時間から収益を計算し、オフライン収益を最大8時間に制限。再開時に獲得量を伝える。連続実行はおおむね毎秒更新し、タブ非表示中に二重計上しない。
- 有限な数値だけを扱い、購入・時間経過・転生・保存データを検証する。巨大数は読みやすい短縮表記にする。50〜90万程度までの進行でも数値が破綻しない。

## 構成とデータ

依存パッケージや外部APIを増やさず、既存の静的HTML/CSS/ES module/Node test/GitHub Pagesを使う。`src/game.js` は純粋なゲーム計算（状態、購入、tick、転生）、`src/storage.js` はバージョン付き保存検証とlocalStorage、`src/presenter.js` は表示用数値と解放状態、`src/app.js` は入力・描画・タイマー・保存、`src/pwa.js` と `sw.js` は更新・オフラインを担当する。UIはスマートフォンで操作しやすい縦並びを基調とし、狭い幅でも横スクロールを生まない。

新しい保存キー `moonlight-idle:v1` を使う。旧キー `moonlit-sorting-office:v1` は読み込まず、削除もしない。保存の `version` は新ゲーム用に独立させる。破損・未知版は安全な初期状態を返し、保存不能でもセッション中は遊べる。エクスポート／インポートは今回の必須機能ではない。別端末への同期はしない。

Service Workerは旧キャッシュ名と異なる新しいアプリ専用名へ変更し、インストール対象にすべての新規モジュールとアイコンを含める。旧SW制御中の初回更新でも新しい `index.html` がネットワークから取得され、次回のオフライン起動で新作が開くことを検証する。GitHub Pagesの `/moonlit-sorting-office/` サブパスで相対URLが動作する。

## 検証

ゲーム計算の赤→緑テストで初期クリック、設備費の増加、購入不能、複数資源、星屑解放、転生条件、恒久倍率、オフライン上限、無効保存を確認する。数値シミュレーションで初回転生が合理的な操作時間で可能であり、同条件の2周目が早まることを確認する。ブラウザでクリックから設備購入、時間生産、星屑、転生、保存再読み込み、スマホ幅、PWAオフラインを実操作する。公開後、同じURLのHTML/manifest/SWと実ブラウザで新作反映を確認する。

## 範囲

完全ローカルのシングルプレイ。広告、課金、サーバー、アカウント、ランキング、前作データのゲーム通貨への変換は扱わない。旧保存を削除しないため、前作の記録はブラウザ内に残る。
